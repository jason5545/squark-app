# fex/highball

FEX for a runtime with `FEX_SERIES=highball`, from
[highball-engine](https://github.com/gauthierpiarrette/highball-engine) `fex/` at `2eedc50`, unchanged:

- `0001` to `0033`, Highball's series for FEX 2610 (`fex/patches/` there, whose README explains each
  one). They pair with Wine's `patches/wine-11.18-fex` 0022 to 0052, and the same patches in
  `patches/wine-11.21-highball`. MIT, like FEX.
- `fexunixlib_darwin.cpp`, the unix helper FEX's Windows DLLs load from the ntdll.so directory, with
  BSD calls and hardware TSO through `thread_set_x86_64_compat`. It replaces FEX's own
  `Source/Windows/UnixLib` (and `fex/0001-macos-hardware-tso.patch`): `0019` and `0023` add calls
  (`AliasWrite`, `ZeroPages`) that only this helper has. MIT.

With `0018` hardware TSO is on in every thread. Hadron turned it off by default because Ubisoft
Connect deadlocked with it (6bb8d87); Highball runs Microsoft Flight Simulator 2024 with it on.
The switches for programs that rewrite their own code (`HB_FEX_*`) are off unless a game sets them.

## Ours (squark), on top of Highball's series

Measured on squark's `tools/wasm-bench` FBW A380X systems benchmark (Rust to WebAssembly, wasm2c, x64),
the stand-in for the WebAssembly gauges of Microsoft Flight Simulator's add-on aircraft. Highball's
upstream has a `0034` of its own (MAP_JIT backfill), not taken here; ours start at `0035`.

- `0035`: the entry of a block a call returns to stores the block header but skips the suspend check;
  the callee's entry made one. -1% host instructions.
- `0036`: `ExitFunctionEC` keeps the JIT's FPCR for memcpy, memmove and memset of Wine's builtin
  ucrtbase, msvcrt and ntdll (no floating-point arithmetic in their ARM64EC code), saving the two FPCR
  writes of each such call. -5% cycles on the benchmark.
- `0037`: `SQUARK_FEX_ABI_FLAGS=<path piece>;...` treats flags as dead across calls and returns in the
  listed modules (compiler output only, never a protected executable). Off without the variable.
  -3.6% instructions with the benchmark listed.
- `0038`: LEA with a 32-bit destination uses 32-bit adds. -2% instructions.
- `0039`: entry points no longer store the block header (`CPUState::InlineJITBlockHeader`); each code buffer keeps
  its block starts and the fault, suspend and self-modifying-code paths find the block from the host PC. On the TFDi
  MD-11 WebAssembly replay (squark `md11-bench`, x64 build without wasm2c's per-call depth count) -6% cycles per
  frame (9.96M -> 9.37M), A380X -1.7%. `SQUARK_FEX_ENTRY_HEADER=1` brings the store back. squark's
  `tools/fault-test` checks the RIP of faults in entry, return and loop blocks.
- `0040`: an erased block's entry points exit to the dispatcher. Each entry point starts with a nop that
  `GuestToHostMap::Erase` turns into a branch to an exit stub at the end of the unit (store RIP, clear the L1 slot,
  dispatcher), and reinstatement turns back; the dispatcher enters a unit it has just compiled past the nop. Host
  code that still led into an erased block (call-return predictions, L1 slots, links) ran the old translation after
  the guest rewrote it: JavaScriptCore's JIT asserted in about one run in twenty (Bun 1.4.4 x64), and squark's
  `tools/smc-subpage` S9 (a callee rewrites the instruction its call returns to, another thread writes the page) got
  the old value in a third of the calls; both none with it. `SQUARK_FEX_STALE_EXIT=0` turns it off.
- `0041`: `HB_FEX_SMC_HOT_MAXINST` (Highball's cap for units on pages a write fault invalidated, 64 in the MSFS recipe)
  no longer caps units in a JIT engine's code pool, a private executable reservation of 256 MB or more such as
  JavaScriptCore's 1 GB one (Coherent GT's gauges, Bun). The pool's pages are written now and then, so nearly all of
  JavaScriptCore's code ran as small units ending at every call. Bun 1.4.4 with the A380X gauges: PFD -9% instructions,
  -15% cycles per frame, the 24 gauges 4.31 -> 3.94 ms per frame (median of three); WebAssembly benchmarks and
  Highball's SMC tests unchanged. `SQUARK_FEX_HOT_JITPOOLS=1` caps pools again.

- `0042`: `SQUARK_FEX_EC_STATS=<Windows path>` counts which native functions x64 code calls through `ExitFunctionEC`,
  per thread (a ring the exits write, a worker that rewrites the file every 5 s with the 400 most frequent
  {thread, target} pairs and their images). For measuring only; off without the variable.
- `0043`: x64 code calls listed native functions without FPCR leaving the JIT's mode. `ExitFunctionEC` wrote FPCR on
  the way out (to drop AH, NEP and the trap enables) and the dispatcher wrote it back on the way in; on Apple cores
  each write waits for everything in flight. The list is `FPCRNeutralTable.inc`, generated by `../fpcrscan.py` from
  the same build's ntdll, kernelbase, kernel32, ucrtbase and msvcrt when the runtime is built (`build-wine.sh`, before
  FEX compiles): every function from which nothing reachable does floating-point data processing, writes FPCR or
  makes an indirect call it can't follow. Paths end where Wine patch 0070 drops the JIT's bits (syscall and unix call
  dispatchers, debug output, the ARM64EC syscall wrappers) and at FEX's own exports, which drop them first thing now.
  An image is used only when its name, TimeDateStamp and `.text` size match the build scanned. The targets sit in a
  hash set of 32768 slots instead of 0036's list of 16. `SQUARK_FEX_FPCR_TABLE=0` leaves the table out. Per x64 call
  under FEX: `GetLastError` 26.3 -> 4.7 ns, `TlsGetValue` 26.2 -> 4.6 ns, `EnterCriticalSection` +
  `LeaveCriticalSection` 59.8 -> 13.6 ns, `AcquireSRWLockShared` + `ReleaseSRWLockShared` 70.8 -> 25.0 ns; the table
  covers 54 % of Microsoft Flight Simulator's exits in the cockpit (72 % of the main thread's).
  0043 needs Wine patch 0070 in the same runtime.

Measured on Apple M5 Max: the call/return path of call-dense code is bound by its stores and the memory-ordering
flushes around them, not by instruction count, so 0035-0038 cut instructions without cutting cycles there.

Wine loads FEX from the prefix's `C:\windows\system32\xtajit64.dll`, not from the runtime's
`lib/wine/aarch64-windows`: a prefix made with an older runtime keeps its old FEX until that copy is
replaced.
